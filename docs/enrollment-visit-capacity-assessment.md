## Pickup/logistics exception control

Existing scheduled arrangements remain the planning baseline when no contrary evidence exists. No shared pickup pool, service frequency, numerical capacity or cross-site resource competition is assumed. Lab/Logistics interfaces are relevant because collection visits require pickup and sample receipt; exact specimen-by-visit requirements remain unspecified.

**Approved fictional operational planning rule:** confirm readiness **2 working days before each scheduled pickup**, using the existing Monday-Friday calendar without holiday exclusions. Count backward from the actual planned pickup date, excluding that date. For a Monday pickup, the checkpoint is the preceding Thursday; for Tuesday it is the preceding Friday. A weekend pickup, if actually scheduled, also uses backward weekday counting. No pickup is invented from a visit date, and collection is not assumed to equal dispatch or Lab receipt.

Apply the rule to known scheduled events; absent pickup dates remain an evidence gap rather than a fabricated calendar. A checkpoint may fall before the Apr 12 assessment boundary for a pickup early in the horizon; the rule still applies, without asserting historical confirmation occurred.

Use the existing Lab/Logistics arrangement and relevant site input under the RACI; CRO/Lead coordination does not create vendor-ownership or approval authority. Successful confirmation supports proceeding with that event's plan, but does not guarantee performance, prove broader vendor capacity, or create an SLA, vendor commitment or protocol requirement. It is not demonstrated response capability.

If confirmation identifies a timing/capacity concern, assess the exception's affected visit, specimen movement and downstream dependency through existing issue/risk/governance rules. Reassess if contrary information arises after confirmation. Do not assume resolution is possible within two working days, invent mitigation, or transfer the courier exercise contingency.
